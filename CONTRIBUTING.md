# Working rules
1. Each student commits her own work from her own GitHub account.
2. Branches: `main` is the stable version. Work in branches named `kamila/<research and requirements>` or `akbota/<technical design and prototype>`; merge through a pull request that the other student reviews.
3. Commit messages: `type: short description (YouTrack ID)`, e.g. `docs: add requirements specification (LEX-12)`. Types: docs, diagram, design, plan, fix.
4. Every deliverable lives in its folder. Diagrams are committed as PNG.
5. Never commit passwords, API keys or `.env` files.
6. A task is done when: the other student reviewed it, it is committed to the correct folder, and the YouTrack task is closed.
7. Before submission both students check all folders.
